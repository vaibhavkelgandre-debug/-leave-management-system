<!-- Functional Requirements


Module 1: Accounts, Roles & Reporting Structure -->

<!-- FR-001: Employee Invitation -->
HR administrator can add a new employee.
Employee receives an invitation link.
Employee sets their own password.
Real email delivery is not required; displaying or logging the invitation link is sufficient.


<!-- FR-002: Secure Password Storage -->

Passwords must never be stored or logged in plain text.




<!-- FR-003: Social Login -->

Employee can log in using at least one OAuth 2.0 provider.
Supported providers may include Google or GitHub.
If the OAuth email matches an existing employee account, both accounts must resolve to a single user account.



<!-- FR-004: User Roles -->

System must support three roles:

Employee
Manager
HR Administrator

Everyone is an employee.

Managers and HR have additional permissions.

<!-- FR-005: Reporting Structure -->
Every employee has exactly one manager.
The top-level employee has no manager.
Reporting structure forms a tree.
Cycles are not allowed.

Example:

CEO
 ↓
Manager
 ↓
Employee

Invalid:

A → B

B → C

C → A




<!-- FR-006: Role-Based Access -->

Employee can:

View own leave

Manager can:

View own leave
View team leave
Approve/reject team requests

HR can:

View everything

Authorization must be enforced on the server.

<!-- Module 2: Leave Types, Entitlements & Calendar

FR-007: Leave Type Management -->

HR can create leave types.

Each leave type contains:

Name
Annual entitlement
Upfront or monthly accrual
Allow negative balance
Supporting document required


<!-- FR-008: Leave Balances -->

Every employee has balances for each leave type.

Balance includes:

Entitlement
Days taken
Days pending
Days remaining


<!-- FR-009: Half-Day Leave -->

System supports:

Half-day at start
Half-day at end


<!-- FR-010: Holiday Calendar -->

HR maintains public holidays.

Working day calculation excludes:

Weekends
Public holidays


<!-- Module 3: Leave Requests & Approval Workflow -->
<!-- FR-011: Submit Leave Request -->

Employee submits:

Leave type
Start date
End date
Half-day flags
Reason



<!-- FR-012: Document Upload -->

If leave type requires documents:

Employee uploads supporting document.
File type validated.
File size validated.
Validation performed on server.
Document visible only to:
Employee
Approver
HR


<!-- FR-013: Working Day Calculation -->

Before submission:

System calculates leave days excluding:

Weekends
Public holidays

<!-- FR-014: Balance Validation -->

System rejects leave if:

Balance becomes negative

unless

Leave type allows negative balance.

<!-- FR-015: Overlap Detection -->

Reject request if it overlaps:

Pending request
Approved request

of the same employee.
<!-- 
FR-016: Leave Request State Management -->

Supported states:

Submitted
Approved
Rejected
Withdrawn
Cancelled

Illegal state transitions must be rejected.

<!-- FR-017: Manager Approval -->

Manager can:

Approve
Reject
Add comments

Only for employees in their team.


<!-- 
FR-018: HR Override -->

HR can:

Approve
Reject
Override manager decisions

Override must be recorded.

<!-- FR-019: Withdraw & Cancel Leave -->

Employee can:

Withdraw:

Pending leave

Cancel:

Approved future leave

Both restore leave balance.

<!-- FR-020: Delegation -->

Manager can nominate delegate.

Delegate can approve requests only during:

Start date
End date

Audit records:

Actual actor
Manager represented


<!-- FR-021: Audit Trail -->

Every request stores:

State changes
Actor
Timestamp
Comments

Audit trail is append-only.


<!-- Module 4: Dashboards & Reporting


FR-022: Employee Dashboard -->

Employee can view:

Leave balance
Request history
Personal calendar


<!-- FR-023: Manager Dashboard -->

Manager can view:

Pending approvals
Team calendar


<!-- FR-024: HR Dashboard -->

HR can:

View all requests
Filter by:
Employee
Leave type
Status
Date range

Generate:

Leave report

Download:

CSV
